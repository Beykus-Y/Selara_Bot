# Чек-лист ручной проверки Telegram UX (issue #184)

Проверяет пользователь вручную на реальных клиентах Telegram. Автотесты покрывают
тексты, callback-маршрутизацию и права на backend; клиентское поведение (вёрстка
кнопок, перерисовка, deep links, slash-меню) проверяется только здесь.

Перед проверкой: бот перезапущен на версии с PR-H, в ЛС и в тестовой группе
есть аккаунт-участник и аккаунт-администратор.

## Клиенты

- [ ] Telegram Android
- [ ] Telegram iOS (если доступен)
- [ ] Telegram Desktop

## Скриншоты /start

- [ ] Первый запуск, без групп (аккаунт без истории в группах)
- [ ] Обычный участник с группами («👥 Мои группы» есть, «🛠 Управление группами» нет)
- [ ] Администратор хотя бы одной группы («🛠 Управление группами» есть)
- [ ] Текст помещается на один экран телефона без прокрутки; ссылок-превью под сообщением нет

## Сценарии A–I (issue #184, раздел 7)

**A. Новичок, ни одной группы**
- [ ] /start → за один экран понятно, что делает бот
- [ ] «➕ Добавить в группу» открывает выбор группы Telegram (flow добавления бота)
- [ ] «✨ Возможности» → «Игры и развлечения» → доходим до игры без знания команды
- [ ] В любой точке «🏠 Главное» возвращает к /start

**B. Личный AI**
- [ ] /start → «🤖 Личный AI» открывает меню Personal AI
- [ ] Обычное сообщение в ЛС уходит к AI, а не в настройку
- [ ] «⬅️ Назад» и «🏠 Главное» на экранах Personal AI работают
- [ ] Если AI недоступен, виден понятный статус без обещаний

**C. Гача**
- [ ] /help → «Игры и развлечения» → «Гача» → Genshin / HSR
- [ ] Фразы запуска соответствуют реальным (нет кнопки «крутить в ЛС», если механика в группе)

**D. Семья и кланы**
- [ ] /help → «Общение» → «Семья» и «Кланы» открываются, пример синтаксиса виден
- [ ] Возврат к разделу отношений работает

**E. Питомцы**
- [ ] /help → «Питомцы» → «Начать» даёт короткий сценарий
- [ ] Бесплатные действия отделены от функций, требующих Personal

**F. Администратор нескольких чатов**
- [ ] /start → «🛠 Управление группами» → выбор конкретного чата
- [ ] «⚙️ Управление группой» → тематическая категория (например, «🤖 AI и итоги дня») → изменение настройки
- [ ] Возврат к карточке выбранной группы; контекст другого чата не подменяется

**G. Чужой /help в группе**
- [ ] Один участник вызывает /help в группе
- [ ] Другой участник нажимает разделы и читает их без отказа «это меню другого пользователя»
- [ ] Персональные действия (настройки, подписки) по-прежнему отказывают чужому пользователю

**H. Старые сообщения и ссылки**
- [ ] Клавиатура, отправленная до обновления, открывает корректный экран или подсказку открыть /start
- [ ] Deep link `/start game_<id>` открывает роль игры как раньше
- [ ] Deep link `/start eco_<chat_id>` открывает экономику группы как раньше
- [ ] Навигация не списывает монеты, не меняет квоты и не открывает оплату

**I. Негативные сценарии**
- [ ] Навигация во время ввода значения настройки: после «🏠 Главное» следующее сообщение не уходит в настройку
- [ ] Два быстрых нажатия подряд не дают ошибку и traceback
- [ ] Длинное название группы с символами `<`, `&` отображается без поломки HTML
- [ ] После перезапуска бота старые кнопки не падают

## /help в оживлённой группе

- [ ] Несколько участников одновременно открывают разные разделы одной карточки — текст не ломается, нет зависших «message is not modified»
- [ ] Новые сообщения от бота не плодятся при каждом клике (редактируется одна карточка)

## Slash-меню

- [ ] В ЛС: /start, /help, /ai, /memory и другие личные команды видны
- [ ] В группе: групповые команды видны, /ai_reset, /memory, /forget_all, /autocfg — нет
  (после смены меню Telegram может показывать старый список до перезапуска клиента)

## Итог

- [ ] Все сценарии A–I пройдены на каждом клиенте, из которого есть возможность
- [ ] Найденные расхождения записаны в issue #184 с клиентом и скриншотом
